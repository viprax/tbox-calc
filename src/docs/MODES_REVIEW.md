# Пересмотр простого и экспертного режимов

Дата: 2026-11-15. Задача: все пять пунктов «Задача для Сола» из PLAN.md. Это рекомендация перед переработкой интерфейса, а не отметка о реализации нового UI.

## Решение

Два режима полезны, если помогают решить разные задачи в одном проекте. Рекомендуется сохранить простой режим по умолчанию как подбор и объяснение результата, экспертный — как проверку параметров, ограничений и изготовления. Выбор режима меняет представление, но не исходные параметры, источник объёма для акустики или результат. Для ФИ применять тот же принцип после завершения его геометрии; сейчас переключатель режимов есть только у ЗЯ.

Рассмотрены три подхода:

| Подход | Польза | Ограничение |
|---|---|---|
| Одна страница с раскрытием дополнительных полей | Меньше переключений | Новичок всё ещё сам выбирает порядок решения задачи, сложнее выделить проверку конструкции |
| Два независимых калькулятора | Можно сильно упростить первый | Дублирование данных, ошибки при переносе проекта и расходящиеся результаты |
| Два сценария одного проекта | Подбор для новичка и проверка конструкции для специалиста с общими данными | Нужно явно отделить выбор расчётного объёма от режима интерфейса |

Рекомендация — третий подход. Она сохраняет существующие названия, палитру и черновики. Существенную перестройку экранов следует показать владельцу перед реализацией, как он просил ранее.

## Что должен делать пользователь

| | Простой: подобрать и понять | Экспертный: проверить и подготовить |
|---|---|---|
| Основная задача | Сравнить варианты объёма и понять влияние на бас | Проверить параметры динамика, реальную геометрию и возможность изготовления |
| Динамик | Выбор пресета, видимый признак ручных параметров, переход к их редактированию | Fs/Qts/Vas, источники и единицы, монтажные размеры и вычеты |
| Объём | Желаемый объём, понятное объяснение цели и результата | Целевой и фактический объём, материал, ручные размеры, ниша, распорки |
| Результат | График, нижняя граница баса, короткое описание формы кривой и ближайшее действие | Qtc/fc/f3/пик, график, 2D/3D, посадка, чертёж и допущения |
| Потери и салон | Короткий выбор/включение с контекстной подсказкой | Явные Ql и параметры условной поправки салона |
| Ошибки | Что мешает расчёту и кнопка к нужному полю | Полная валидация и причины геометрических конфликтов |
| Завершение | Перейти к проверке конструкции с текущими значениями | Проверить посадку и детали перед изготовлением |

Не обещать новичку «качество баса» по одному Qtc. Для специалиста ценность создают не дополнительные поля сами по себе, а проверка источников, воспроизводимость расчёта, отличие цели от полученной конструкции и проверяемый чертёж.

## Что обнаружено в текущем приложении

1. `SealedBoxDraft` уже общий; mode/view хранятся вместе с параметрами. `useSealedDraft` сохраняет его в localStorage `tbox.sealed-draft.v1`. `evaluateSealedDraft` не зависит от режима. Переключение поля mode само по себе не сбрасывает остальные параметры; экспертный вид сохраняется при возврате из простого.
2. Однако `ClosedBoxPage` переопределяет result: simple вызывает closedBox по draft.vb, expert берёт model.calculation.response по геометрии. Это реальное расхождение графика и метрик при тех же входах. Его ввели, чтобы изменение целевого объёма отражалось на кривой, когда монтажный минимум EDGE удерживает геометрию около 40,51 л. Возврат к неподвижной кривой не решает задачу подбора.
3. Тест `sealedDraft.test.ts` проверяет равенство selector, но не равенство реально показанных результатов страницы. Поэтому зелёный набор тестов не доказывает эквивалентность режимов UI.
4. Старый отчёт 12 ноября и scripts/sealed-modes-smoke.py описывают прежнее поведение и подписи. Сейчас этот browser smoke ожидает устаревшую метрику 0,40 и старое название поля объёма. Перед реализацией нового сценария его нужно актуализировать и использовать для приёмки, не выдавать старый успешный запуск за текущую проверку.
5. При известных вычетах, но несовпадении цели, SealedVolumeBalance пишет «График рассчитан по этому объёму» (геометрии) даже в simple, где фактически показана цель. Текст требуется связать с общим источником акустического объёма.
6. Простой режим перегружен повторениями: цель в поле и большом блоке, несколько пояснений про прогноз/вычеты/геометрию, затем «Что дальше». Подсказка Fs/Qts постоянно занимает отдельный блок. Рекомендация: один статус результата и одна следующая операция; справку о выборе корпуса раскрывать по запросу. Критичные ошибки оставлять видимыми.
7. Смена пресета намеренно обновляет TS и размеры динамика, вытеснение и центр установки, сохраняя цель, режим и настройки корпуса. Это другая операция, не переключение режима: показать, какие параметры заменятся, если есть ручные правки. Не называть смену пресета безопасным сохранением всех полей.

## Общее состояние и источник результата

Не создавать второй draft для простого режима. Расширить существующий проект явным полем `responseBasis: "target" | "construction"` и хранить его независимо от mode. Названия для пользователя: «Подбор объёма» и «По размерам корпуса». Это выбор того, что рассчитывается, доступный в обоих режимах; mode определяет подробность управления.

- `target`: акустический объём = введённый целевой Vb. Изменение Vb меняет прогноз в обоих режимах. Геометрические ограничения показываются как проверка возможности изготовления и не подменяют выбранную цель.
- `construction`: акустический объём = объём по размерам минус введённые вычеты. Изменение цели не обязано менять график при фиксированных размерах; рядом явно указать фактический объём. Применять эту основу отдельным действием, а не при открытии экспертного режима.
- При неизвестном вытеснении construction должен явно оставаться предварительным; не объявлять чистый объём подтверждённым. Нельзя молча считать неизвестный вычет достоверным нулём.
- Единый selector возвращает geometry, targetResponse, constructionResponse, selectedResponse, responseVolumeL, responseBasis, warnings и validity по областям. График, курсор, метрики и предупреждения используют один selectedResponse; 2D/3D/чертёж — одну geometry.
- mode/view — настройки представления. Изменение mode не запускает подмену основы, автоприменение пресета или пересоздание исходных данных.
- Ошибку акустических входов показывать в обоих режимах без старых метрик. Ошибка центра выреза блокирует монтажные виды, но не акустическую кривую. Некорректная геометрия не должна ломать независимый целевой прогноз, но всегда блокирует готовность к изготовлению. Некорректную активную поправку салона показывать явно.
- «Принять расчётный объём» меняет цель только явным действием; подпись сообщает, меняется ли основа графика. Не менять другие параметры.
- Кодек: версия 2, поддержка чтения v1. Для старого simple восстановить target, для старого expert — construction, сохраняя прежний результат после reload; затем основа не зависит от переключений. Сохранить NaN/Infinity, ручные значения и данные пресета. Не хранить производные метрики в localStorage.

Новые поля не требуют изменения акустических формул или коэффициентов. Различие заключается в явном выборе входного объёма для тех же функций.

## Переходы и проверка

В отдельном профиле Orca проверены первый запуск, простой → экспертный → простой, восстановление ручного черновика после reload и повторный переход. Пользовательский профиль не очищался. Машиночитаемые замеры находятся локально в `docs/reports/2026-11-15-modes-review-evidence.json`.

Браузерные значения на новом EDGE при 20 л и Ql10: simple — Qtc 0,50, fc 60,8 Гц, f3 94,3 Гц; expert — 0,40, 48,5 Гц, 101,4 Гц. При ручном Fs31, размерах 450×420×300 мм и вычетах 4+1 л: expert — 0,38, 43,6 Гц, 99,0 Гц; simple — 0,50, 58,3 Гц, 90,5 Гц. Сравнение полного сохранённого draft без поля mode подтвердило отсутствие потерь ручных параметров.

По текущему коду выбранный пресет/ручной TS, размеры, вычеты и экспертный вид хранятся в общем draft. Переход сохраняет их, однако отображаемый результат меняется. Это дефект согласованности сценариев, а не потеря введённых данных.

## Критерии готовности будущей переработки

- [ ] Новый пользователь начинает с простого режима и основы target; источник результата указан возле графика.
- [ ] Одинаковые параметры и responseBasis дают одинаковые график, метрики и предупреждения в обоих режимах; сравнивать данные страницы и SVG, а не только selector.
- [ ] EDGE: изменение цели с 20 на 30 л меняет кривую target в обоих режимах даже при монтажном минимуме 40,51 л.
- [ ] Ручные размеры 450×420×300 мм, вычеты 4+1 л: construction даёт 51,7 л независимо от режима; простое переключение сохраняет основу, пресет, ручные параметры и экспертный вид.
- [ ] Смена target/construction — явное действие; все тексты и предупреждения соответствуют выбранной основе.
- [ ] Пресеты EDGE/JL обновляют только предусмотренные данные динамика; ручные правки не теряются без объяснения операции.
- [ ] Reload, v1→v2, пустые/ошибочные поля, неизвестные вычеты, повреждённое/недоступное хранилище проверены отдельно.
- [ ] В simple есть доступ к исправлению любой скрытой ошибки; нет ложного статуса готовности при невозможной посадке.
- [ ] Клавиатура, фокус после перехода к полю, Escape подсказки, reduced motion и ширины 320/390/768/1440 проверены в браузере.
- [ ] Актуализированные browser smoke, unit-тесты страницы, полный Vitest, lint и build проходят; скриншоты осмотрены.

Это критерии реализации следующего этапа, а не уже выполненные проверки нового поведения.
