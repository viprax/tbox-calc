# AGENTS.md: инструкции для агента в проекте TBox

## О проекте
TBox - веб-калькулятор акустических коробов для автомобильных и домашних динамиков.
Сейчас считает закрытый ящик (sealed) и фазоинвертор (ported). Интерфейс на React + TypeScript + Vite + Tailwind.
Пользователь - разработчик-любитель, пишет по-русски, работает на Ubuntu.

## Стек и команды
- Пакетный менеджер: pnpm. Не использовать npm для установки зависимостей.
- Команды: `pnpm dev`, `pnpm build` (включает `tsc -b`), `pnpm vitest run`.
- Тесты лежат в `src/test/core/` и запускаются Vitest.
- Конфиг Vitest находится в `vite.config.ts`, поле `test.include` указывает на `src/test/**/*.test.ts`.

## Структура кода
- `src/core/` - чистая математика, без React и без DOM. Ничего не импортирует из `components/`, `pages/`.
- `src/components/` - переиспользуемые куски интерфейса.
- `src/pages/` - экраны. Сейчас `ClosedBoxPage` и `PortedBoxPage`.
- `src/data/` - тексты подсказок (`hints.ts`), справочные данные.
- Константы пока разбросаны по файлам. Вынос в `src/core/constants.ts` запланирован на момент, когда логика порта стабилизируется. Не выносить без явной просьбы.

## Правила кода
- Импорты относительные (`../core/closedBox`), алиас `@/` не использовать.
- Расширения `.ts` и `.tsx` в импортах не писать.
- Внутри расчётов единицы: Гц, литры, см, см², мм, Ом, мГн, Тл·м, г, дБ, Вт. Перевод только на входе и выходе.
- Все входы проверяются через `assertPositive` / `assertFinite` из `core/assert.ts`, ошибка называет параметр.
- Тексты предупреждений и подсказок лежат отдельно (`warnings.ts` и `data/hints.ts`), менять их без изменения логики.
- Стили только через Tailwind, отдельный CSS не создавать.
- Не использовать `sudo` для установки пакетов или глобальных npm-пакетов.

## Модели и что проверено
Закрытый ящик (`core/closedBox.ts`):
- Формулы Тиля-Смолла, fc, Qtc, f3, горб.
- Потери в ящике: `1/Qtc = 1/Qtc0 + 1/Ql`, Ql по умолчанию 10 (как в JBL SpeakerShop и WinISD).
- Сверено с SpeakerShop на четырёх объёмах (10, 20, 40, 7.96 л): fc, f3, Qtc совпадают.
- Численная проверка интегратора и формулы ФНЧ пройдена.

Фазоинвертор (`core/portedBox.ts`, `core/portedResponse.ts`):
- Настройка Fb по формуле Гельмгольца с поправкой на концы трубы (1.7·r). Сверено с SpeakerShop по геометрии.
- АЧХ 4-го порядка по Herzog и Hilsamer, DAFx-14, на основе Small (1973). Частота нормируется на √(fs·fb), a1 и a3 различаются.
- Сверено на одном случае (Vb 190 л, Fb 30 Гц, Ql 10): среднеквадратичное расхождение 0.14 дБ.
- Второй случай (Vb 80, Fb 40) ещё не сверен.

Не проверено и условно:
- Xmax Edge EDS15D1-E7 в даташите не указан, в коде стоит 20 мм (условно). От него зависит скорость в порту.
- Sd 750 см² - оценка по Vas и Cms (мастер брал так же). SpeakerShop считает 1123 см² из диаметра 38 см. На закрытый ящик и на АЧХ порта Sd не влияет, только на скорость в порту.
- Cabin gain (`core/cabinGain.ts`) - условная модель колоколом по логарифму частоты, не сверена.
- Пороги предупреждений (Qtc, Vb, Xmax, скорость в порту) - ориентиры, не стандарт.

## Что нельзя делать
- Не выдавать формулы за проверенные без сверки с программой или первоисточником. Если формулы нет в источнике, сказать об этом.
- Не подгонять коэффициенты под программу. Сначала найти причину расхождения, потом менять формулу.
- Не менять пороги и тексты без явной просьбы.
- Не удалять тесты, чтобы сделать сборку зелёной. Если тест падает, сначала понять, ошибка в коде или в тесте.
- Не пушить в `main` без проверки `pnpm build` и `pnpm vitest run`. Работа ведётся в ветке `dev`.

## Ветки
- `main` - деплоится на Vercel. Только проверенное.
- `dev` - рабочая ветка, сюда идут все эксперименты (фазоинвертор, сравнение, константы).

## Что отложено
- Вынос констант в `constants.ts`.
- Размеры короба для фазоинвертора (с учётом трубы и отверстия).
- Двумерные проекции короба (SVG) с размерами. Следующий приоритет.
- Трёхмерный вид короба (изометрия на SVG), после двумерного.
- Мобильная версия и тач-управление графиком.
- Сверка фазоинвертора на втором варианте (Vb 80, Fb 40).
