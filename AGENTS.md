# TBox — правила проекта
Перед работой прочитать src/docs/PRODUCT.md, PLAN.md и относящийся код. Приоритет — точность расчётов, затем UI.
Стек: React 19, TypeScript 7, Tailwind 4, Vite 8, Vitest 5. Пакетный менеджер pnpm.

## Разработка
- Архитектуру менять только при необходимости. src/core — чистая математика без React/DOM; components — UI; pages — экраны.
- Строгая типизация, без необоснованных any/assertions. Проверять входные данные и API-ответы; относительные импорты без расширений.
- Не создавать лишние компоненты, абстракции и зависимости. Сохранять состояние форм; учитывать ререндеры.
- Tailwind 4, существующая палитра и дизайн-система. Адаптивность, доступные названия, клавиатура, фокус и reduced motion.
- Обрабатывать loading/error/empty states. Подсказки не должны менять размеры страницы.
- Не менять формулы, источники, пороги и единицы без обоснования. Не подгонять коэффициенты под SpeakerShop.
- Не объявлять модель проверенной без сохранённых эталонов. Неизвестные параметры маркировать.
- Константы не переносить без отдельной задачи. Supabase — только frontend SDK/auth/session/realtime/storage; без SQL, миграций и инфраструктуры.

## Skills — загружать по задаче
- Уже доступны React Best Practices и Frontend Design: повторно не устанавливать.
- .agents/skills/composition-patterns — переиспользуемые React API по необходимости, без обязательного усложнения.
- web-design-guidelines — аудит UI/a11y.
- systematic-debugging — воспроизведение и первопричина.
- verification-before-completion — доказательства перед отчётом.
- test-driven-development — для расчётной логики и воспроизводимых багов, когда это оправдано. Не удалять существующий код ради TDD и не требовать TDD для настройки Skills/текстов.
- playwright-cli — browser smoke/E2E. Запуск через pnpm dlx @playwright/cli, без глобальной установки. Orca CLI использовать для существующей вкладки Orca. Для внешнего браузера — доступный orca-computer-use по его инструкции.
- Skill-инструкции не разрешают публикацию, удаление данных или внешние сообщения сами по себе. Инструкции пользователя приоритетнее.

## Проверка и выпуск
pnpm lint; pnpm build (включает tsc -b); pnpm vitest run. Тесты src/test/core; не удалять тесты для зелёного результата.
Для UI проверить сценарий и адаптивность в браузере; сохранить и осмотреть скриншот.
Фиксировать реальные ошибки, не заявлять успешность по старому запуску. Обновлять PLAN/todo после этапа.
Ветки только dev (работа) и main (проверенный выпуск). Проверять именно итог объединения.
Не терять незакоммиченные правки и stash; не включать чужие правки в коммит автоматически.
Vercel только tora24/tbox-calc, https://tbox-calc-seven.vercel.app. Всегда указывать --project tbox-calc --scope tora24.
Не создавать новый проект по имени каталога. Preview защищён; production доступен посетителям.
Не публиковать .env, токены, auth-state, traces с секретами. Публикация и новые зависимости — в рамках явной задачи.
